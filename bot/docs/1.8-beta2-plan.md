# 1.8 beta 2: controls, notifications and remaining game work

## Scope and decisions

Interface zoom means the macro workspace, assumed from the request; it does not zoom Roblox. The available steps are 80/90/100/110/125%, saved locally, with buttons under Input & Display and Ctrl + / minus / 0 shortcuts. The title bar and compact HUD stay at native size. Drag coordinates account for zoom; changing zoom cancels an active reorder drag.

“W spain” was a title tag and startup celebration. Both are removed. It was unrelated to the bounded W hold after respawn, which is preserved.

Training contains Discord notifications near the after-run controls. Notifications are off until configured and enabled. Final outcomes include completion, manual Stop and errors. Optional progress intervals are 5/10/15/30/60 minutes, sampled from the training loop; pauses or recovery can delay these updates. Messages carry only outcome, elapsed time and an allowlisted trait. No screenshots, chat, raw failure reasons, logs or mentions are sent. Send test is an explicit action and works with routine notifications disabled.

The URL is encrypted using Windows user-scoped DPAPI in `json/notifications.dpapi`, outside normal config and diagnostic exports. Another process running as the same Windows user can decrypt it; this is protection at rest, not a boundary against that user. Only HTTPS webhook URLs on discord.com are accepted. The HTTP client does not follow redirects. A bounded queue, five-second network timeout and no automatic retries keep notification failures out of input timing. A 429 pauses delivery for five minutes. Saving or removing invalidates queued messages; an in-flight message may finish. If removal fails, automatic notifications stop for this session, the failure is shown, and Remove remains available to retry before restarting. Factory reset removes the webhook; ordinary settings reset preserves it.

Shutdown uses a 60-second timer inside XynMacro. Cancel is visible in the expanded banner and compact HUD. Stop, another Start or orderly app close cancels the timer. An app crash ends the timer process too. At expiry the callback commits a Windows shutdown request without forced app closure. Cancellation after that commit cannot be promised; the UI reports requesting/requested/failed/unknown rather than claiming success. No `shutdown /a` is issued, so the app does not cancel another program's Windows countdown. It does not control shutdowns from older XynMacro versions either.

## Deferred game features

These are not implemented or presented as working toggles. Chat was explicitly deferred by the user; the other features need the controls and visual evidence below. Put the eventual options together under **Training → Recovery & resources**, alongside Senzu.

| Feature | Evidence needed | Acceptance and failure handling |
| --- | --- | --- |
| Hide chat only when open | Small screenshots of the topbar chat button in open and closed states, excluding messages; variations for hover, unread badges and scaling | Confirm state before clicking; unknown means no click. Stop/focus/death checks, single click and closed-state confirmation. Never blind-toggle. |
| Recharge Ki from yellow/depleted to dark blue/max | Actual charge controls and screenshots of the relevant bars and thresholds. The claimed dark-blue benefit is unverified | Bound the charge attempt, confirm completion and release held input on Stop, focus loss or death. Do not interrupt minigame input or overlap healing. |
| Majin / Bio-Android healing instead of Senzu | Actual race abilities, keys, restrictions, cooldown/resource costs and visible success cues | User selects race and preferred recovery method. Serialize healing, Senzu and charging; avoid retry loops when cooldown/resource requirements fail. Any fallback should be explicit. |
| Re-equip weights after respawn | Inventory placement, equipped/unequipped cues and how respawn affects them | Wait for a usable character/inventory; equip only when needed and confirm. Bound retries; skip a missing item. Preserve configurable respawn settling and walking. |

Do not infer keys or detector thresholds from rumours. Resume with evidence for one feature at a time, then exercise its Stop/focus/death/recovery paths before enabling it by default.

## Validation and release

Python tests cover DPAPI round-trip using a synthetic webhook, invalid inputs, save/removal failures, queued/in-flight invalidation, rate limits, countdown cancellation and stale timers. Power commands and network sends are mocked. Browser checks cover both themes, narrow widths, zoom, drag reordering, notification drafts/save, and cancellation in expanded/compact modes. The frozen-sidecar smoke saves and removes a disabled synthetic webhook without sending a message, checking that its URL is absent from state.

No real shutdown, real webhook message or Roblox input was used for development verification. Native WebView2 interaction and actual Discord delivery still need user acceptance. Install subsequent betas manually; the beta update feed is pinned to its release tag. Stable remains separate.

Protocol references: [Microsoft shutdown command](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shutdown), [Discord webhook reference](https://docs.discord.com/developers/resources/webhook).
