# 1.8 beta audit and acceptance record

Scope: active Tauri frontend, input/recovery paths, settings persistence, local HTTP authentication/commands, theme import/rendering, updater/release configuration, and dependency advisories. Solo source review; not an independent penetration test. No live Roblox inputs were sent.

## Confirmed findings addressed

| Finding | Impact | Change and evidence |
| --- | --- | --- |
| Click injection discarded the Windows accepted-event count | A partial click could leave the button held while telemetry continued | Check down/up delivery, attempt release of the same button on partial delivery, surface failure; regression test includes a setting change between packets |
| Respawn walking started immediately after the death dialog disappeared | A slow-loading character could miss some or all movement | Configurable 0–30 second settling delay; bounded hold; Stop/focus/error release tests |
| Key tap had no `finally` release around the hold | An exception during the hold could skip key-up | Release in `finally` |
| Theme override objects were passed through to root CSS properties | A deliberately imported theme could alter layout rather than only colours | Restrict overrides to seven exposed colour tokens and six-digit hex colours; 64 KB import limit; malformed/theme-injection tests |
| Malformed command objects could fail before the route's exception handler | Invalid JSON shapes produced an internal error | Reject non-object/string-action envelopes with HTTP 400; 1 MB body limit; isolated real Flask handler test |
| Queue drag assumed 40 px rows | Wrapped labels could move the wrong distance | Use measured row height; cancel dragging on pointer cancellation/window blur; keyboard ordering retained |
| Resize button used an undefined generic button class | Native-looking control in a styled app | Use existing button component; browser-rendered check |
| Delay label described key hold duration | Users tuned the wrong quantity | Label now describes post-tap delay and its shared scope |
| Competing window-mode switches | Both could be enabled with implicit precedence | One atomic startup window-mode choice; preserve both original values on failed save |

## Existing boundaries inspected

- Packaged sidecar requires the launch token; host/origin/token tests cover denial paths. The token is passed through stdin, not command-line arguments.
- Rust loopback clients disable redirects, keeping their custom auth header from following redirects to another host.
- Public announcements and logs use text insertion at their external-data sinks. Imported theme overrides are now constrained.
- Bug-report URLs are rebuilt by the backend for the configured GitHub issue destination; no arbitrary frontend URL is accepted by that action.
- Existing Stop gates, Senzu input serialization, update signing checks, and manual-stop exclusion from after-run actions are preserved.
- Beta CI configuration uses its own application identifier and product/binary names. Prereleases use a tag-specific updater URL; the stable latest-release URL is unchanged.

## Dependency results

- Python requirements audit: no known vulnerabilities in the resolved set (including transitive packages). This is an advisory result, not proof of security.
- Node lockfile audit: zero reported vulnerabilities.
- Rust full lockfile audit: no blocking vulnerabilities, nine warnings: six unmaintained packages, two unsoundness advisories (`event-listener`, `glib`), and yanked `chacha20`. Windows dependency-tree checks found no active `event-listener`, `proc-macro-error`, or `chacha20` path. Unmaintained `unic-*` packages remain through `urlpattern`; avoid an unrelated forced dependency rewrite. Release CI reruns the audits.

## Verification

- 310 Python tests plus 34 subtests passed after the input, recovery and command fixes.
- 45 frontend tests passed, including the new theme validation tests.
- Local Cargo tests passed (5 tests).
- Headless Edge rendered Classic and Aero at 1100, 800 and 640 px with a mock backend, plus a compact 800 × 32 preview. Checked queue overlap, click-button/window-mode saves, inactive-mode controls, search and uncaught UI errors. No page errors. This is browser evidence, not native WebView2/game acceptance.
- `bot/scripts/smoke_frontend.cjs` reproduces the UI check with Playwright and Edge. Set `PLAYWRIGHT_MODULE` if using a separately installed Playwright module. It closes its browser and saves screenshots under the system temporary directory.

## Remaining acceptance and risks

- Health/Ki restart-after-hit stays OFF by default. Real game progress retention, timing and throughput are unverified; counters indicate sent inputs rather than earned progress.
- The friend's third-party remapper needs a live test. Windows button swapping and a remapping program may interact differently.
- Respawn settling is a delay after dialog dismissal, not character-ready detection. Movement direction remains camera-relative.
- Main-loop metrics include waits and detection work; they are not game FPS or individual capture rates. Inner ring/WASD timings are unchanged. Slower-PC benefit needs measurement.
- Do not run beta and stable simultaneously: separate app profiles still share system hotkeys and game input. Beta uses separate settings and calibration; stable remains installed and untouched.
- Source-only launches retain the pre-existing unauthenticated development fallback. This was not expanded to packaged builds. CSP still permits the existing inline event handlers; removing that permission requires converting and testing those handlers first.
- TypeScript migration remains incremental follow-up work. The new theme validator has typed JSDoc, but no full frontend TypeScript migration or typecheck gate is claimed.
- The portable style kit is a static reference, not a website deployment or wired application.

Stop the beta, close it, and reopen stable to return to the previous release. Do not copy beta configuration over stable while gameplay acceptance is pending.
